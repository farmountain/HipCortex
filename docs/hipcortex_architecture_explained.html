What Is HipCortex? Overview

Imagine you hire a brilliant contractor but every morning they wake up with complete amnesia. You tell them "build me a house." They start, make some decisions… then forget everything overnight. Next day you start over. That's every AI agent today.

HipCortex is the persistent brain you bolt onto any AI agent. It remembers goals across sessions, tracks beliefs about the world, learns which actions lead to which outcomes, simulates future trajectories, and — critically — knows when its own beliefs are wrong and fixes them.

Think of it as three things fused together: a diary (memory), a mental model (world model + digital twin), and a self-critic (coherence + error recovery).

Memory Layer

Goals, beliefs, decisions, observations — all typed records with SHA-256 integrity, Merkle audit chain, WAL crash recovery, AES-GCM encryption.

Intelligence Layer

Self-model (capability tracking), world model (transition learning, Kalman entities, causal graph), coherence (contradiction detection, conflict resolution).

Continuous Layer

Digital twin with RK4 integrator, causal SCM (structural equations, do-calculus, counterfactual credit assignment). Physics-style simulation of task state.

Surfaces

REST (Axum), gRPC (Tonic), MCP stdio (45 tools, 7 resources), Python SDK, TypeScript SDK, VS Code extension.

Entry Point — MCP Auto-Injection Passive

Before a class starts, a good teacher reads their notes from last week. They don't wait for a student to ask "what did we cover?" — they walk in already knowing the context.

MCP resources work the same way. The moment a Claude Code session starts, HipCortex automatically shoves relevant memories into Claude's context window — no tool call needed, no prompt engineering required. Claude walks into every task already briefed.

Three MCP resources auto-inject at session start (via hipcortex:// resource URIs):

ResourceWhat it loadsUse case
hipcortex://context/relevant Top-k semantically similar past memories to current task Past decisions, prior failures, architectural choices
hipcortex://beliefs/current Active Symbolic records (user preferences, project facts) "User prefers TypeScript", "project uses PostgreSQL"
hipcortex://context/conversation Recent Temporal traces for current actor (HIPCORTEX_ACTOR) What happened in last N interactions
Key insight Fresh session → nothing injected (blank slate). Returning session → Claude arrives with full context of past decisions, failures, and beliefs. This is why HipCortex eliminates "re-explain the project" overhead on every new session.

Hot Store vs Cold Store

Your working desk (Hot Store) only has files you're actively using. Archived boxes in the basement (Cold Store) have old files — still retrievable for audits, but not cluttering your workspace.

Semantic search targets Hot Store only by default — active, unconflicted records. Superseded beliefs and decayed traces move to ArchiveStore (Cold Store) via ArchiveStore::archive(). Pass include_archived: true for audit queries. Never set status = "archived" on a live record — that pollutes Hot Store searches.

Phase 1: Goal Creation & Storage MemoryStore

When you give a mission to a squad, you write it on a whiteboard with clear success criteria: "Deliver package to address X by 5 PM — success when: package signed for, recipient confirms receipt." Not vague instructions — a typed contract with measurable exit conditions.

HipCortex Goal records are exactly that. Not "build Facebook" as a string — a structured record with urgency, cost estimate, and a checklist of things that must be true before the goal is "done."

What MemoryStore does on every write

1. SHA-256 integrity hash computed

Hash of record content stored inline. On load, recomputed and compared — tampered records rejected instantly.

2. WAL (Write-Ahead Log) entry appended

Operation logged before data written. If crash occurs mid-write, WAL replays on restart — zero data loss.

3. Merkle audit.log chain extended

Each record's hash feeds into the next chain link. Any retroactive tampering breaks the chain — forensically detectable.

4. AES-GCM encrypted (if configured)

Envelope encryption via MemoryStore::new_encrypted(). Key stored separately — records unreadable without it.

5. GoalScheduler re-ranks

Ranks all Pending/InProgress goals by urgency / estimated_cost. High urgency + low cost = top priority. Returned on every cognitive_report as "next recommended action."

GoalScheduler formula priority = urgency / estimated_cost. Facebook (0.9 / 0.4 = 2.25) beats a low-urgency documentation task (0.3 / 0.5 = 0.6). Always returns the highest-ratio pending goal as "what to do next."

Phase 2: ReactEngine — The Cognitive Heartbeat loop_engine.rs

A chess grandmaster doesn't just move pieces randomly. They observe the board, reflect ("if I move here, opponent does that, then I lose the bishop..."), then act with the best move. Then they observe the response, reflect again, act again. That loop — Observe → Reflect → Act — is how intelligent agents work.

ReactEngine is HipCortex's implementation of that loop, but for AI tasks. Each iteration writes evidence to memory, so the loop is not just in RAM — it's permanently recorded and auditable.

CognitiveDelta — The Transaction System

A bank never just changes your balance — it records a transaction: who, what amount, when, why. That transaction is the unit of change, not the raw number. You can replay all transactions to reconstruct any historical balance.

CognitiveDelta is the transaction for cognitive state. Every state change is a typed delta that gets validated, applied, and audit-logged atomically.

// All deltas that can change cognitive state:
enum CognitiveDelta {
    AssertGoal(GoalPayload),
    RetractBelief { id: Uuid },
    AssertJustification { belief_id, justification },
    WorkspaceOpen { mode: Private | Shared },
    WorkspaceMerge { workspace_id },
    AutoConsolidate { min_frequency },

    // v1.2.0 — Causal SCM operators:
    Intervene { var: String, value: f64 },
    Counterfactual { query: String },
    CreditAssign { trajectory_ids: Vec<Uuid> },
    RewriteStructuralEquation { node_id: String, new_weights: Vec<f64> },
}

// Every delta goes through CognitiveState::transact_ex():
// 1. CoherenceChecker validates preconditions
// 2. SafetyGuardrail::check_precondition gates mutation
// 3. apply_delta(&delta, actor) executes with lock discipline
// 4. TxLog records the operation (tx_cursor incremented)
// 5. Reflexion audit record written

Lock Order (Critical — Never Violate)

Deadlock prevention rule Lock order is always: world (RwLock read) → causal_graph (RwLock write) → memory (Mutex). Never hold two simultaneously if acquiring in a different order. Each apply_delta arm acquires locks, does work, drops immediately before next acquire.

Phase 4: World Model — Learning from Every Action world_model_enhanced

A weather forecaster has three tools: (1) a history of weather patterns — "when it's humid like this, it usually rains" (Dirichlet transitions). (2) A sensor that tracks temperature right now — even through noise (Kalman filter). (3) A map of causes — "low pressure causes clouds, clouds cause rain" (causal graph).

HipCortex's World Model has exactly these three sub-models, firing in parallel on every observation.

Sub-model 1: Dirichlet-Multinomial Transitions

Imagine a coin that isn't necessarily fair. Every time you flip it, you update your estimate of P(heads). Start with a weak prior (could be anything), then each observation sharpens the posterior. A Dirichlet distribution is the generalization of this to many outcomes — not just heads/tails, but "auth_done", "auth_failed", "auth_partial"...

// Every ReactEngine observation fires WorldModelUpdater:
observe(state: "auth_started", action: "implement_oauth", next: "auth_done")
  → transition_counts[("auth_started", "implement_oauth", "auth_done")] += 1

// Posterior predictive (Laplace smoothed):
P(s' | s, a) = (count(s, a, s') + α) / (Σ_s' count(s, a, s') + K·α)

// After enough iterations on the Facebook build:
P(auth_done | impl_oauth)  = 0.73
P(auth_fail | impl_oauth)  = 0.21   // learned from past failures
P(auth_part | impl_oauth)  = 0.06

P(deploy_ok | tests_pass, staging_ok) = 0.87   // strongly concentrated
Self-improving The model gets sharper every iteration. Session 1: uncertain priors. Session 10: confident posteriors based on real observed transitions. This is the "learning" that survives across sessions.

Sub-model 2: Kalman Entity Tracking

A submarine captain knows their speed and heading, so they can estimate position — but error accumulates over time. When they get a GPS ping (an observation), they update their estimate, weighted by how much they trust the GPS vs their dead reckoning. That's a Kalman filter: blending a physics-based prediction with noisy observations to get the best estimate.

HipCortex tracks entities like "build_progress", "budget_remaining", "sakura_bloom_date" the same way — predicting with a model, correcting with observations.

PREDICT x̂ₖ = F·xₖ₋₁ ← project state forward (e.g., "build_progress grows at 5%/day")
Pₖ = F·Pₖ₋₁·Fᵀ + Q ← uncertainty grows without observations
UPDATE Kₖ = Pₖ·Hᵀ·(H·Pₖ·Hᵀ + R)⁻¹ ← Kalman gain: how much to trust observation vs model
x̂ₖ = x̂ₖ + Kₖ·(zₖ - H·x̂ₖ) ← pull estimate toward observation (zₖ = Claude's reported value)
Pₖ = (I - Kₖ·H)·Pₖ ← uncertainty collapses after good observation

For the Kyoto trip: sakura_bloom_date has prior mean=Apr 5, uncertainty=±5 days. As real bloom forecasts arrive (observations zₖ), the estimate sharpens. If a forecast says Mar 28, Kalman update pulls estimate earlier, reduces uncertainty.

Sub-model 3: Causal Graph with Structural Equations (v1.2.0)

Correlation isn't causation — everyone knows this. But intervention reveals causation. If you vaccinate a group (an intervention — do(vaccine=1)) and disease drops, that's causal, not just correlated. Judea Pearl's do-calculus formalizes exactly this.

HipCortex's causal graph tracks not just "A happens before B" but the actual structural equations that generate the relationship: B = f(A, noise). This lets us do two things correlation can't: (1) simulate interventions before doing them, (2) assign blame when things go wrong.

// Facebook causal graph edges (built from observations):
db_setup  ──[weight 0.9]──→  api_layer
api_layer ──[weight 0.85]──→ auth
auth      ──[weight 0.8]──→  posts
posts     ──[weight 0.9]──→  feed
feed      ──[weight 0.75]──→ chat
chat      ──[weight 0.95]──→ deploy

// Kyoto causal graph:
bloom_date       ──→ crowd_level
bloom_date       ──→ best_viewing_spots
crowd_level      ──→ optimal_visit_time
best_spots       ──→ day_plan_quality
accommodation    ──→ transport_efficiency
jr_pass          ──→ day_trip_feasibility

// Each node has a StructuralEquation f_i(parent_inputs, noise):
// LinearSE implements: output = weights · inputs + noise_term
// Evaluable: compute forward. Invertible: solve for inputs given output.

do-calculus — Interventions

// Two intervention modes:

// 1. Persistent (apply_intervention) — mutates shared graph in-place:
causal_graph.apply_intervention("sakura_bloom_date", 20240328.0)
// → removes all incoming edges to bloom_date (severs existing causes)
// → pins bloom_date = Mar 28 permanently
// → all downstream nodes (crowd_level, best_spots) recompute from this fixed value

// 2. Simulation (do_operator) — clones graph, leaves original intact:
let simulated = causal_graph.do_operator("deploy_readiness", 1.0)
// → safe to rollout without affecting live cognitive state

Phase 5: Digital Twin — Continuous Simulation digital_twin.rs

NASA doesn't just send a rocket to Mars and hope. They have a digital twin — a full simulation of the rocket running in parallel. They test maneuvers in simulation first. If the twin shows the fuel will run out, they fix the plan before burning real fuel.

HipCortex's Digital Twin does this for tasks. It models the project as a continuous state vector (a list of numbers representing "how done is each component") and uses physics-style integration (RK4) to simulate how the state evolves as actions are taken — before committing to them in reality.

State vector design

Facebook replica (dim=7)

[db_readiness, api_coverage, auth_status, frontend_progress, test_coverage, ci_passing, deploy_readiness]

Each dimension: 0.0 (not started) → 1.0 (complete).

Kyoto trip (dim=6)

[days_planned, budget_used, transport_booked, accommodation_booked, attractions_selected, bookings_confirmed]

Budget dimension: 0.0 (none spent) → 1.0 (fully allocated).

RK4 Integration — step(action)

Euler's method of integration is like walking in a straight line at your current velocity — it accumulates error. Runge-Kutta 4 (RK4) is like checking your velocity four times per step (at start, two midpoints, end) and averaging them. Same cost, 4× accuracy. Used in flight simulators, spacecraft navigation, game physics engines.

// step(action: &str) → new state vector
let k1 = f(xₙ, action);
let k2 = f(xₙ + dt/2·k1, action);
let k3 = f(xₙ + dt/2·k2, action);
let k4 = f(xₙ + dt·k3, action);
xₙ₊₁ = xₙ + dt/6·(k1 + 2k2 + 2k3 + k4);

// v1.2.0: After RK4, clamp pinned intervention variables:
for (var, pinned_val) in &self.pinned {
    let dim = self.var_to_dim[var];
    xₙ₊₁[dim] = *pinned_val;   // causal impulse overrides ODE dynamics
}
// This means: if you intervene on "deploy_readiness = 0" (blocked),
// the RK4 physics can't push it above 0 — causal constraint wins.

Phase 6: Error Handling — When Things Go Wrong Four classes

A good scientist doesn't just admit they were wrong — they have a protocol: detect the anomaly, trace which assumption failed, update the model, rerun the prediction. Ad-hoc "oh it broke, fix it" is engineering. Systematic detection → tracing → updating is science.

HipCortex has four distinct error classes, each with its own detection instrument and recovery chain. Think of them as four different kinds of "wrong" an AI agent can be.

🔴 Error Class A — World Model Prediction Wrong

Scenario: ReactEngine predicted auth_done after implement_oauth. Test suite reports 8/12 tests fail. The world model was wrong about this transition.

Detection — CalibrationTracker (EWMA)

EWMA (Exponentially Weighted Moving Average) is like a memory that forgets the past gradually. Recent errors count more than old ones. If you keep making big prediction errors recently, EWMA spikes — your calibration score falls. A weather forecaster who was wrong the last 5 days has bad calibration right now, even if they were good last month.

prediction_error_ewma = α · |predicted - observed| + (1-α) · prev_ewma
// α = 0.1 typically — recent errors weighted 10%, history weighted 90%

// When ewma > threshold:
calibration_score    ↓   // self-model knows it's less reliable
epistemic_entropy    ↑   // beliefs become more uncertain
ExecutionGate        →   // may block high-stakes actions until recalibrated

Recovery Chain

1. Temporal record written

ReactEngine observe step: action="auth_test_failed", metadata: {failed_count: 4, error: "JWT expiry mismatch"}

2. Dirichlet automatically reweights

transition_counts[("auth_started","implement_oauth","auth_failed")] += 1. No code to write — the next P(s'|s,a) query returns the updated posterior. Self-healing.

3. BeliefInvalidator decays related beliefs

Scans Symbolic records citing implement_oauth as reliable. Applies: new_conf = old_conf × (1 - contradiction_score × 0.3). If conf drops below 0.2 → archives belief to Cold Store.

4. EmergenceDetector may synthesize new Belief

If "JWT expiry mismatch" pattern appears in ≥5 Temporal records in last 50 → auto-creates Belief: "JWT libraries have breaking changes in v2.x" with evidence pointers.

🟠 Error Class B — Digital Twin State Drift

Scenario: Twin predicted test_coverage = 0.8 after 3 sprints. Actual measurement: 0.4. The physics model was wrong — RK4 dynamics overestimated progress velocity.

Detection — sigma_norm spike + GoalDistanceDrift

// Kalman covariance matrix grows when predictions repeatedly miss:
continuous_sigma_norm = ||Pₖ||_F   // Frobenius norm of covariance matrix

// Goal distance drift alarm:
||x_current - x_goal||₂ > drift_threshold
// → current trajectory won't reach goal state in time

Recovery Chain

1. Kalman update corrects state estimate

Observation zₖ = 0.4 (actual). x̂ₖ = x̂ₖ + Kₖ·(0.4 - 0.8) — pulls estimate from 0.8 down toward 0.4. Kalman gain Kₖ determines how aggressively. Pₖ = (I - Kₖ·H)·Pₖ — uncertainty collapses post-update.

2. CognitiveDelta::Intervene pins corrected value

apply_intervention("test_coverage", 0.4) — removes incoming edges to test_coverage node in causal graph, pins at 0.4. Future RK4 clamps this dimension to 0.4 — model can't drift above it without explicit update.

3. Rollout re-run from corrected state

Previous trajectory was based on x=0.8. New rollout from x=0.4 gives accurate future projection. GoalDistanceDrift alarm may trigger re-planning.

4. SafetyGuardrail gates the intervention

SafetyGuardrail::check_precondition runs before any causal graph mutation. Logs to audit trail. If precondition fails (e.g., intervention would violate acyclicity), it's rejected.

🟣 Error Class C — Causal Structural Equation Wrong

Scenario: Causal graph assumed deploy_readiness driven by test_coverage alone. Reality: it's gated 30% by tests, 70% by security_audit. The structural equation was miscalibrated.

Detection — AAP Triad (CreditAssign)

Counterfactual reasoning: "If only the OAuth token had been correct, would auth have worked?" You hold everything else constant, change just that one thing, and see if the outcome changes. If it does — that's the cause. Abduction (find noise), Action (pin it), Prediction (rerun) — Pearl's three steps for counterfactual analysis.

// ABDUCTION: find noise variables consistent with observed outcome
U_deploy = observed_deploy_readiness - f_deploy(PA_deploy)
//          actual 0.3              - predicted 0.7 = -0.4 residual
// → the deploy structural equation is off by 0.4

// ACTION: pin all noise variables at abducted values
apply_intervention("test_coverage", observed_test_val)   // hold constant
apply_intervention("security_audit", observed_audit_val) // hold constant

// PREDICTION: re-run structural equations forward
predicted_deploy_new = f_deploy_with_abducted_noise(PA_deploy)
// if this still ≠ observed → deploy structural equation is the broken one
// CreditAssign returns: node_id = "deploy_readiness" as the culprit

Recovery Chain

1. CreditAssign identifies broken equation

Returns: node_id = "deploy_readiness" with evidence that test_coverage weight should be 0.3, security_audit weight 0.7.

2. CognitiveDelta::RewriteStructuralEquation applied

{ node_id: "deploy_readiness", new_weights: [0.3, 0.7] } → transact_ex → apply_delta → acquires world.read() → causal_graph.write() → calls rewrite_structural_equation.

3. Reflexion audit record written

"Structural equation rewritten after credit assignment: deploy_readiness weights [0.5,0.5]→[0.3,0.7], evidence: 3 observed deployments." Full audit trail with actor, timestamp, prior/posterior weights.

4. SystemInvariants re-checked

Acyclicity: no new cycles from rewrite. Decay monotonicity: confidence decay still one-directional. Conservation: total belief mass within bounds. If any invariant fails → rollback.

🟢 Error Class D — Coherence Violation (Contradictory Beliefs)

Scenario: Kyoto trip — two beliefs: "peak sakura Apr 5–10" (conf 0.8, from 2023 data) and "peak sakura Mar 28–Apr 5" (conf 0.7, from 2024 JMA forecast). Contradiction — both can't be true.

Detection — ConsistencyChecker

// ConsistencyChecker scans all Symbolic records pairwise:

Two Integration Profiles

Profile 0 — Zero Config (Passive)

Agent doesn't call add_memory at all. Passive observers capture automatically:

• HipCortexCallbackHandler — LangChain
• HipCortexCrewObserver — CrewAI
• HipCortexAutoGenObserver — AutoGen
• VS Code extension — file saves + terminal

All observers fail silently — never raise, never slow the agent loop.

Profile 1 — Standard (Explicit)

Agent explicitly calls SDK tools. Full control over what gets stored and when.

• HipCortexClient.add_memory() — Python
• HipCortexClient.addMemory() — TypeScript
• add_memory MCP tool
• make_memory_tools() — inject into CrewAI agent tools

Best for: structured goal-driven workflows.

The One-Paragraph Summary

When you give Claude Code a complex task with HipCortex installed: Step 1 — past context auto-loads from memory into Claude's window before anything happens. Step 2 — the task becomes a typed Goal record with measurable success criteria, SHA-256 integrity, and full audit trail. Step 3 — ReactEngine loops Observe→Reflect→Act, writing evidence records at every step that are linked by provenance. Step 4 — every observation automatically trains three parallel models: a probability model (what transitions are likely), a physics model (where are entities right now), and a causal model (what causes what). Step 5 — if a Digital Twin is created, it simulates the future as a continuous state vector via RK4 integration with causal clamping, so you can ask "if I do X then Y, where will I end up?" before committing. When things go wrong, HipCortex has four recovery mechanisms: EWMA calibration (wrong predictions → beliefs decay, model reweights), Kalman correction (drifted state → observation snaps estimate back to reality), AAP credit assignment (wrong causal equation → identified and rewritten with full audit), and conflict resolution (contradictory beliefs → resolved by recency/confidence, loser archived). Everything — memories, mutations, interventions, rewrites — flows through SafetyGuardrail and is permanently logged to a Merkle-chained audit trail. The result: an agent that remembers, learns, simulates, self-corrects, and knows why it made every decision.
